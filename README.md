# webdnf · 阿拉德档案

独立的 DNF 玩家门户工程。当前是**可直接运行的静态交互原型，不是真实玩家后台**；所有角色、属性、装备、公告和模拟榜单均为虚构数据。没有框架、第三方运行依赖或构建步骤。

## 本地运行

安装 **Node.js 22 或更高版本**，然后：

```sh
git clone https://github.com/PlsGoodBoy/webdnf.git
cd webdnf
npm run dev
```

打开终端显示的 `http://127.0.0.1:4173`，输入小写 **`admin`** 进入演示，**不需要密码**。首尾空格会忽略，其他用户名不能进入。

```sh
npm start                  # 同样启动本地静态预览
npm run dev -- --port 5180 # 端口被占用时改端口
npm test                   # Node 内置回归与 HTTP 测试
npm run check              # JS 语法、JSON 格式与全部测试
```

不需要执行 `npm install`；没有依赖需要下载。预览仅监听 `127.0.0.1`，只提供 `dist/` 文件，支持正确的 `.mjs` MIME、HEAD、404 和路径越界保护。它不是生产后端，也不代理游戏接口。请通过 HTTP 打开，不能直接双击 `file://`。

## 已保留的功能

- 演示登录、刷新恢复当前标签页演示标记、退出重置；`admin` **不代表管理或 GM 权限**。
- 总览、本人 3 个样例角色的搜索/切换、属性与装备、公告弹窗。
- 右下可拖动服务器游标 → 状态小窗 → 玩家动态对话框；**没有独立服务器页面**。
- 账号卡片「签到」只展开「尚未接入，奖励与重置时间待配置」说明；不发奖、不生成签到记录。
- 独立排行榜：团本攻坚成功次数（可选团本）、深渊成功入场次数、**历史最高强化 `+N`、历史最高增幅 `+N`**，后两者不是操作次数。
- 服务器状态默认未知、榜单默认空；主动开启才显示明确标注的静态虚构示例。服务器与榜单模拟开关独立，刷新/退出会重置。
- 响应式布局、键盘操作、焦点恢复、原生模态对话框和减少动画偏好。

## 目录

```text
dist/                      手写前端源文件；直接作为静态站点根目录
  app.mjs                  DOM 事件、演示会话、焦点管理
  data.mjs                 mockAdapter、状态转换、虚构数据
  views.mjs                渲染与原创 SVG 图形
  floating.mjs             拖动边界与阈值纯函数
  index.html / styles.css / mark.svg
scripts/preview.mjs        零依赖 localhost 静态预览
scripts/check.mjs          JS 语法及 JSON 检查
tests/                     业务、事件、HTTP 与路径安全回归
config/backend.example.json 后端规划示例，不会被当前程序加载
docs/architecture.md       当前结构与安全边界
docs/api-contract.md       当前适配器 + 待实现 HTTP 契约草案
docs/next-steps.md         后续独立后端接入路线与验收
.github/workflows/check.yml Node 22/24 检查，不包含部署
```

`dist/` 不是编译产物，请直接修改并提交它。`.env.example` 仅示范本地预览端口，默认启动不会自动读取 `.env`；如需使用，复制后运行 `node --env-file=.env scripts/preview.mjs`。禁止把密码、会话、GM 密钥或数据库连接信息写入前端、示例配置或 Git。

## 演示边界

- `sessionStorage` 只保存标签页演示标记，不是认证，不能保护真实玩家数据。
- 前端不调用网络 API、不读取数据库、不生成或替换游戏 token。刷新只是重载静态样例，不查询在线状态。
- 未知值用 `null/未知`，不能以 `0` 代替。角色数不等于服务器在线人数；当前装备不等于历史最高纪录。
- 深渊规则已确定为**服务端确认成功入场计 1 次**，未打完/退出仍计，失败入场不计，同局重试/重连不得重复计数。真实事件来源、业务时区与换日时间仍待确认。
- 不含真实登录、GM、充值、交易、邮件发奖、背包/经济写入；未验证游戏联机、数据库或协议兼容性。

下一步建议从独立 Go（或其他语言）只读门户后端开始，不把游戏服务、密钥或数据库暴露给浏览器。具体见 [架构](docs/architecture.md)、[接口草案](docs/api-contract.md)、[接入步骤](docs/next-steps.md)。自动化测试包含轻量 DOM 事件桩，不替代真实浏览器视觉、触摸和键盘验收。
