# 后续接入与验收

当前工程已经可以本地运行、修改与测试；下列均是后续工作，**没有创建或启动真实后端**。

## 1. 先确认数据与身份边界

- 确认实际游戏服务版本、部署方式、授权访问范围和账号来源，核实账号/角色映射。不同来源的账号表不能凭相似字段混用。
- 逐段检查现有认证流程是否生成/替换游戏 token 或断开旧游戏会话；网页登录必须独立，不能影响正在游戏的玩家。
- 为角色/装备/位置、完整在线快照、深渊成功入场、团本成功、历史最高强化/增幅分别列出可信来源和缺失字段。
- 确认业务日时区、换日时间、统计起点/历史覆盖、公开名单/榜单隐私规则。没有证据的字段继续未知。

## 2. 实现最小独立门户后端

可选择 Go 标准库 HTTP 服务（或熟悉的其他技术），独立于游戏服务；先完成 Web 会话、本人角色列表和只读详情。不需要迁移现有前端框架，也不要先造一个声称真实的 mock 后端。

建议边界：HTTP handler → 会话/归属检查 → 只读门户服务 → 数据适配器。只有实现时再创建 `server/` 与相应模块文件，不预置不能运行的空后端骨架。

`config/backend.example.json` 仅是无密钥设计示例，不会被程序读取，也不是可投入运行的配置。真实凭据使用部署环境的机密管理；开发本地配置不得提交。前端只获得业务数据，不获得数据库、GM 或游戏服务密钥。

## 3. 再逐项接入状态与统计

1. 接入本人角色与装备；逐字段验证含义与单位，保持只读。
2. 独立验证游戏服务健康与完整在线快照，不把账号接口健康等同于全链路在线。
3. 验证允许公开的玩家动态与隐私字段；保留「游标 → 小窗 → 详情对话框」入口。
4. 接入去重的深渊成功入场、各团本成功历史、可信最高强化/增幅事件，标注历史覆盖范围。
5. 用独立网络 adapter 替换演示 adapter，保留明确的演示模式与来源标记；真实 API 失败不得降级成伪实时样例。

签到暂不推进：奖励、资格、重置规则、幂等与审核尚未确认，当前只保留账号卡片提示。无 GM、经济写入或服务端下载/安装。

## 上线前的停止条件与验收

以下任一未通过，就不应接入真实玩家或称为生产可用：

- 账号 A 无法通过修改角色 ID、URL 或直接发请求读取账号 B 的角色。
- 网页登录/退出不轮换游戏 token、不踢掉游戏连接；Web 退出确实使 Web 会话失效。
- 只读查询对游戏数据库没有写入，数据适配器使用最小权限。
- 断网/过期会话/不完整快照正确显示未知或错误，无伪造零值与假数据回退。
- 深渊失败入场不计、退出仍计、同局重试/重连不重计；换日边界按最终业务规则验证。
- 团本成功去重、历史最高强化/增幅与当前装备分开验证；缺失历史不补造。
- 公共名单和榜单只返回允许公开字段，接口限流、会话 Cookie、CSRF、日志脱敏与部署 TLS 已验证。
- 桌面与窄屏实际浏览器：登录/退出/刷新、重复点击、搜索、角色切换、拖动、键盘、Esc/关闭、焦点恢复、独立模拟开关、签到提示均通过。
- 执行 `npm run check`，后端加入自己的单元、接口与越权回归测试；再单独安排部署与备份方案。

当前 CI 仅运行静态工程检查，不部署、不接入游戏。许可与正式部署目标由仓库所有者另行决定。
